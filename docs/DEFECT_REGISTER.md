## Root-cause checks

- **Active ownership.** `ArgonStudioShell` selects `RHWelcomeScreen`, which mounts one lazy `ResidenceShowcase`. Chapter buttons scroll the existing track. The mount effect creates the scene once and disposes its resources on teardown. Source search found no callers of `CinematicWelcomeScene` or `CONSTRUCTION_STAGES` in the active app. `ThreeBuildingScene` and the product's `use3DAnimation` hook are reached through the model workspace and building customizer. [Shell](../packages/frontend/src/components/argon/ArgonStudioShell.tsx#L438) · [Welcome entry](../packages/frontend/src/components/studio/RHWelcomeScreen.tsx#L56) · [Hero lifecycle](../packages/frontend/src/components/studio/ResidenceShowcase.tsx#L256) · [Project model entry](../packages/frontend/src/components/model-3d/ModelWorkspace.tsx#L217) · [Project animation hook caller](../packages/frontend/src/components/argon/Building3DCustomizer.tsx#L68)
- **Visibility, timers and layout.** React conditionally renders the story text and CTA. Geometry visibility is a Three.js Boolean. The app uses native scroll, a scroll RAF, React progress updates and a render RAF. The render loop itself does not call React setters on each frame. No active GSAP or ScrollTrigger participates in the hero. The measured layout work across the six marked actions was 4.75 ms in total, with a 0.93 ms maximum event. Layout thrash was not reproduced as the dominant stall. [Scroll handler](../packages/frontend/src/components/studio/RHWelcomeScreen.tsx#L30) · [Render scheduler](../packages/frontend/src/components/studio/ResidenceShowcase.tsx#L144) · [Trace measurements](PERF_BASELINE.md#frame-timing)
- **Draw submission and shadows.** Instancing is already in place. The current scene had 142 instanced batches and 3,458 instances. Several batches are repeated per floor, and individual balcony plants are instantiated one at a time. Nine transparent double-sided guard batches add work. The sun shadow map is cached at rest. Floor movement repeatedly requests a shadow update on hardware, lifting the observed peak to 272 draws. Frustum culling is enabled for the model batches. The sky dome explicitly bypasses it. [Batching](../packages/frontend/src/components/studio/terrace-residence.ts#L24) · [Individual balcony planting](../packages/frontend/src/components/studio/terrace-residence.ts#L159) · [Sky and shadows](../packages/frontend/src/components/studio/ResidenceShowcase.tsx#L63) · [Floor shadow invalidation](../packages/frontend/src/components/studio/ResidenceShowcase.tsx#L187)
- **Lighting and first-use work.** Evening activation changes which lights are visible. A separate probe observed six new shader program links at first activation and zero on repeat. The clean trace localizes the long waits to the hero callback. Attribution of that wall time to a specific GL operation, driver wait or HDR processing step remains unverified. [Lighting application](../packages/frontend/src/components/studio/ResidenceShowcase.tsx#L155) · [Asset requests](../packages/frontend/src/components/studio/ResidenceShowcase.tsx#L231) · [Performance baseline](PERF_BASELINE.md#first-use-lighting-diagnostics)
